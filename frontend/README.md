# ArchDrift frontend

React + TypeScript + Vite + Cytoscape.js. Локальный прототип работает без бэкенда.

## Запуск

Нужен Node.js 22.12+ в ветке 22 LTS (или поддерживаемая версия 24+).

```bash
cd frontend
nvm use # если установлен nvm; иначе выберите Node.js 22 самостоятельно
npm ci
npm run dev
```

Откройте адрес, напечатанный Vite (обычно http://127.0.0.1:5173).

```bash
npm test        # unit, contract и integration тесты
npm run test:frontend  # unit и integration тесты фронтенда
npm run test:contracts # проверка контрактных фикстур
npm run build  # проверка TypeScript и production-сборка
```

## Данные и интерфейс

Источник архитектуры — `examples/opentelemetry-demo.architecture.json`.
`public/mocks/architecture.json` — сгенерированный файл; вручную его не редактируем.

После изменения эталона:

```bash
cd frontend
npm run mocks:generate
npm run mocks:check
npm run test:contracts
```

Генератор копирует эталон, удаляет единственную декларацию `checkout → email` и
оборачивает модель в ответ API. Ревизия берётся из `analysis.architectureVersion`,
`updatedAt` фиксирован для синтетического снимка. Эталон и `analysis.json` не меняются.
Если нужная связь исчезла или стала неоднозначной, генератор завершается с ошибкой.
Повторный запуск даёт тот же результат. Обновлённый JSON коммитим вместе с эталоном.

`npm run dev` автоматически запускает генерацию перед Vite. Проверка `--check`
ничего не записывает; она входит в контрактные тесты, поэтому CI обнаружит устаревшую
копию. `analysis.json` остаётся отдельной фикстурой наблюдений: при изменении топологии
его нужно согласовать с моделью, метрики и трейсы из CALM не выводятся.

- `public/mocks/architecture.json` — ответ `GET /api/v1/architecture`: CALM 1.2 внутри `model`, версия и время обновления.
- `public/mocks/analysis.json` — ответ `GET /api/v1/analysis`: нормализованный наблюдаемый граф, метрики, нарушения и диагностика.
- Снимок OpenTelemetry Demo (Astronomy Shop) по контракту 0.4.0: 23 сервиса, 61 объявленный endpoint, PostgreSQL и Kafka; 64 наблюдаемые связи. Воркеров в эталонной модели нет.
- `model` взят из `examples/opentelemetry-demo.architecture.json`: ревизия сохранённой модели равна 1, удалена только декларация `checkout → email`. Это сценарий устаревшей модели; эталонный файл не изменён.
- Один `unexpected`: `POST /oteldemo.CheckoutService/PlaceOrder` → `POST /send_order_confirmation`; соответствующее нарушение открывается из правой панели.
- Два `indeterminate`: назначения вызовов `frontend → cart` и `checkout → payment` определены только до сервиса, а декларации задают endpoints.
- Дополнительный `GET /api/experimental` у frontend имеет `known=false`. Вызов из frontend-proxy покрывается широкой декларацией, поэтому он `declared`, а не нарушение. Всего 87 узлов и 62 наблюдаемых/объявленных endpoints; часть объявленных endpoints не наблюдалась.
- Синтетические trace/span IDs показываются как примеры; реальных трейсов и Jaeger в этом прототипе нет.

Переключатель показывает обзор сервисов или endpoints и воркеры внутри сервисов. Поиск оставляет найденные узлы и их непосредственные связи. Фильтр статуса применяется до группировки. Выбор доступен и на canvas, и в раскрывающемся списке с клавиатуры. В боковой панели — подробности связи/узла и переходы к нарушениям.

Большой граф Demo распределён по четырём колонкам; endpoints — строками внутри сервисов. Длинные gRPC-маршруты переносятся на несколько строк без сокращения. Раскладка детерминированная, без физической симуляции. Обзор показывает все сервисы; подробный режим открывается в области нарушения, чтобы 62 метки не уменьшались до нечитаемого размера. «Вписать» показывает весь граф; фон можно перетаскивать, поиск оставляет соседей найденного узла. Кнопки масштаба приближают центр видимой области; процент сбрасывает масштаб к 100%.

В сервисном обзоре группируем по source, target, type, dbOperation: счётчики складываются, длительность усредняется с весами по числу операций. Смешанные статусы сохраняются в деталях; цвет определяется приоритетом unexpected → indeterminate → declared. Это правило отображения, а не повторная проверка CALM.

Мок загружается обычным `fetch`, обновление — кнопкой. Временной интервал фиксированный, фоновый polling не имитируется. `src/api.ts` — место для последующего подключения реальных `/api/v1/architecture` и `/api/v1/analysis?from=…&to=…`. Проверка совпадения версий защищает от смешивания двух моделей.

## Проверки

- Unit: группировка, средневзвешенные метрики, приоритет статусов, фильтрация, поиск, parentId и стабильные ID.
- Contract: структура ответов по OpenAPI, CALM по официальным локальным схемам, ссылки узлов/интерфейсов, владение воркерами и согласованность нарушений.
- Integration: загрузка HTTP-моков, React-состояния, фильтры, выбор и события реального Cytoscape, ошибки/повторная загрузка, очистка ресурсов.
- Регрессия раскладки: отсутствие пересечений узлов демо, стабильные строки endpoints, ограниченные размеры графа, масштабирование относительно центра и обновление индикатора масштаба.

В jsdom Cytoscape работает с настоящим графом, но без canvas-рендерера. Эти тесты не заменяют визуальную проверку в браузере.
